# GPT-Voyager announcement rules

These rules apply to every release announcement unless the user explicitly overrides them.

1. Keep the established bilingual structure:
   - Chinese: 本次更新、中文 — 常用功能、反馈。
   - English: What's new, English — common features, Feedback.
2. “本次更新 / What's new” contains only real user-visible changes in the current release.
3. Do not present issue numbers, internal patches, compatibility plumbing, refactors, generic “UI refresh”, or testing work as features.
4. Do not invent or pad features. If a release contains only fixes, describe only the concrete behavior that is now reliable.
5. Move genuine features introduced by the previous release into both “常用功能 / common features” sections, then remove them from the new release-update section unless they changed again.
6. Keep Chinese and English content semantically equivalent.
7. State the store-review estimate as the current release date plus three calendar days unless the user gives another date.
8. Do not add precautionary backup warnings when the release has been verified and no such action is required.
